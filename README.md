# Inclusive Insight 1.2

*Your Inclusive Education Companion*

Електронний журнал педагогічних спостережень для асистента вчителя: уроки, спостереження, завдання, рівні підтримки, цілі ІПР, досягнення, стратегії, аналітика та звіти.

React + TypeScript SPA/PWA на GitHub Pages. З версії **1.1** дані зберігаються в **Supabase** (PostgreSQL + Row Level Security) і доступні на ноутбуці, телефоні й планшеті після входу за email і паролем. IndexedDB лишається для локальної копії, офлайн-черги змін і чернеток форм. Аналітика та звіти, як і раніше, рахуються в браузері.

| Режим | Коли | Вхід | Де дані |
|---|---|---|---|
| **Хмарний (1.1)** | задано `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase Auth: email + пароль | Supabase (RLS) + локальна копія на пристрої |
| **Локальний (1.0)** | змінні не задано | ім'я (локальний робочий простір, не захист) | лише в цьому браузері |

📘 **Налаштування Supabase і GitHub Pages:** [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md) · **1.2 Smart Schedule:** [docs/CHANGELOG_1.2.md](docs/CHANGELOG_1.2.md) · **1.1 хмара та синхронізація:** [docs/CHANGELOG_1.1.md](docs/CHANGELOG_1.1.md)

> **Важливо.** Використовуйте псевдоніми учнів. У локальному режимі вхід за іменем — це лише перемикач робочих просторів, а не захищена автентифікація.

### Правила статистики

* Показники рахуються лише з реальних записів в IndexedDB.
* Пропущені значення не вважаються нулями: знаменник — лише записи, де показник оцінювався. Поруч із кожним відсотком показано `n`.
* Відсотки виконання рахуються лише в межах однієї одиниці вимірювання (слова з літерами не змішуються).
* Чернетки в статистику не входять.
* За малої кількості даних показується попередження замість висновку.
* Smart Insights — локальний Rule-Based Analytics Engine, не штучний інтелект. Він не робить медичних чи психологічних висновків і не трактує збіг у часі як причину.

## Швидкий старт

Потрібен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тести: аналітика, дані, синхронізація, RLS на справжньому Postgres (PGlite)
npm run build      # production-збірка в dist/
npm run preview    # перегляд production-збірки
```

Щоб одразу побачити наповнений інтерфейс: увійдіть за іменем → **Спробувати демо**. Демо-учень і всі його записи позначені як демонстраційні та видаляються однією кнопкою в *Налаштування → Дані*; реальні записи вони не зачіпають.

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub (наприклад, `inclusive-insight`) і завантажте туди вміст цієї папки:
   ```bash
   git init
   git add .
   git commit -m "Inclusive Insight 1.0"
   git branch -M main
   git remote add origin https://github.com/USERNAME/inclusive-insight.git
   git push -u origin main
   ```
2. На GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Адресу Supabase і publishable key передайте через **Variables** репозиторію `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY` або через закомічений `.env` (див. [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md), крок 3).
3. Workflow `.github/workflows/deploy.yml` запуститься автоматично при кожному push у `main`: встановить залежності, прожене тести, збере проєкт і опублікує `dist/`.
4. Додаток буде доступний за адресою `https://USERNAME.github.io/inclusive-insight/`.

**Чому це працює з будь-якою назвою репозиторію:** у `vite.config.ts` задано `base: './'` (відносні шляхи), а маршрутизація побудована на `HashRouter` (`.../#/journal`). Тому оновлення сторінки на будь-якому маршруті не дає 404, а шляхи до ресурсів і PWA правильні в підпапці. За бажання можна задати явну базу: `BASE_PATH=/inclusive-insight/ npm run build`.

Перевірка після публікації: відкрийте сайт, створіть профіль і запис, оновіть сторінку (запис має залишитися), перейдіть між розділами, сформуйте звіт, вимкніть мережу й перезавантажте — додаток має відкритися офлайн.

## Архітектура

```
src/
  types/models.ts          типи даних (усі записи мають id, ownerId, studentId)
  db/database.ts           Dexie-схема IndexedDB, версії та міграції
  db/repositories.ts       репозиторії — єдиний шар доступу до даних
  analytics/engine.ts      чисті функції метрик, періодів, теплової карти, Smart Insights
  analytics/loader.ts      завантаження даних для аналітики
  reports/reportData.ts    збір даних і автоматичний підсумок звіту
  reports/exporters.ts     PDF (pdfmake), DOCX (docx), XLSX (SheetJS), CSV — ліниве завантаження
  services/backup.ts       експорт/імпорт JSON, перевірки, SHA-256, шифрування AES-GCM
  services/demo.ts         генерація та очищення демоданих
  lib/catalog.ts           довідники варіантів (поведінка, підтримка, предмети, шаблони…)
  hooks/useApp.tsx         сесія: профіль, учень, налаштування, тема
  components/ui            дизайн-система (картки, чипи, модальні вікна, тости, підтвердження)
  components/charts        обгортки над Recharts
  components/layout        Sidebar (desktop), нижня навігація (mobile), PWA-оновлення
  pages/                   сторінки
  schedule/                1.2: scheduleEngine.ts (єдина логіка розкладу), репозиторій, хуки
  cloud/                   1.1: Supabase client, auth, синхронізація, перенесення записів 1.0
  components/cloud         індикатор синхронізації, конфлікти, розділ «Хмара», майстер імпорту
  test/                    vitest + fake-indexeddb + PGlite (RLS)
supabase/migrations/       SQL-схема, тригери версій, RLS-політики
```

UI звертається до даних лише через `db/repositories.ts`. У 1.1 зміни, зроблені через репозиторії, перехоплюються хуками Dexie й надсилаються в Supabase (`cloud/sync.ts`), а дані з хмари записуються в ті самі локальні таблиці. Тому сторінки, аналітика й звіти не потребували переписування.

### Таблиці IndexedDB

`users, students, subjects, lessons, observations, tasks, events, strategies, strategyUses, iepGoals, iepMeasurements, achievements, templates, settings, drafts` + (1.1) `outbox, versions, conflicts` + (1.2) `schedulePeriods, scheduleSlots, scheduleOverrides`

Схема має версії (`version(1)`–`version(4)`) з міграціями; тест перевіряє оновлення наявної бази v1. Відповідні таблиці Supabase мають префікс `ii_` (див. `supabase/migrations`).

## Резервні копії

*Налаштування → Дані → Backup & Restore*

* Експорт усіх даних профілю в JSON із версією формату, версією схеми та контрольною сумою SHA-256.
* Необов'язкове шифрування паролем (PBKDF2 + AES-GCM, Web Crypto API). Пароль ніде не зберігається — без нього файл не відновити.
* Імпорт: перевірка версії, структури й цілісності, попередній перегляд вмісту, вибір **Об'єднати** (дублікати за ID — лишається новіша версія) або **Замінити**, підтвердження, звіт про результат.

Незашифрований файл містить усі нотатки про учня — зберігайте його так само обережно, як паперовий журнал.

## Межі локального збереження (локальний режим)

* Дані зберігаються лише в цьому браузері на цьому пристрої; інший пристрій їх автоматично не отримає.
* Очищення даних браузера може їх видалити. Приватний режим не підходить для тривалої роботи.
* Регулярний експорт резервних копій обов'язковий. У налаштуваннях можна перевірити стан сховища та попросити браузер зробити його постійним (persistent storage).
* Service Worker кешує лише файли додатка; записи з IndexedDB у Cache Storage не потрапляють.

## Конфіденційність

Додаток не містить трекерів. У хмарному режимі дані передаються лише у ваш проєкт Supabase і захищені Row Level Security: кожен акаунт бачить тільки власні записи. У локальному режимі дані не залишають браузер. Водночас для роботи з реальними даними дитини потрібні належні технічні засоби захисту, правові підстави та погодження з адміністрацією закладу. Для тестування використовуйте лише вигадані дані (деморежим).
